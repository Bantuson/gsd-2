# Phase 20.2.3 Plan 03: Tauri Security Hardening, CI SHA Pin, and Configurable Permissions Summary

**One-liner:** Restricted Tauri asset scope to $RESOURCE/$APP, added explicit capabilities file, removed shell plugin, fixed multi-window Bun lifecycle, pinned tauri-action to SHA, and made skipPermissions configurable from preferences.md with a safe false default.

## What Was Built

### C5 — Asset Scope Restricted
`tauri.conf.json` assetScope changed from `["**"]` (full filesystem) to `["$RESOURCE/**", "$APP/**"]`. The `**` wildcard allowed `asset://` protocol to read arbitrary files from the user's filesystem — a critical finding.

### H1 — Capabilities File Created
`capabilities/main.json` created with explicit permission list for the main window. Defines only required permissions: core defaults, window management, dialog, opener, updater, deep-link, window-state, and a restricted oauth-callback event.

### H2 — Shell Plugin Removed
`tauri-plugin-shell` removed from `Cargo.toml` and `lib.rs`. The plugin was initialized but never used by any Rust command — keeping it initialized exposed the frontend to potential `shell:execute` access.

Generated schema files in `gen/schemas/` updated automatically by cargo check to reflect the plugin removal (2 files with shell-plugin entries deleted, 2 manifest files updated).

### M12 — Window Close Fixed
`on_window_event` in `lib.rs` now checks `webview_windows().len() <= 1` before killing the Bun server. The `<= 1` threshold (not `== 0`) accounts for the destroyed window potentially still being in the map when the `Destroyed` event fires.

### H8 — CI Action SHA Pinned
`release.yml` `tauri-apps/tauri-action` pinned from floating `@v0` to SHA `e3a53aa0ef3fd057c1e7397eaef8eaa3f2a5420f` (v0.5.18). Comment added explaining why: this action has access to Apple signing certs, GPG key, and Tauri signing key — a supply chain risk if the tag can be moved.

### H5 — skipPermissions Configurable, Default False
`pipeline.ts` skipPermissions changed from hardcoded `true` to reading `skip_permissions` from `.gsd/preferences.md` YAML frontmatter, defaulting to `false` when file is absent or key is missing. Same logic applied to `switchProject` path. Removed the TODO comment about Phase 13.
