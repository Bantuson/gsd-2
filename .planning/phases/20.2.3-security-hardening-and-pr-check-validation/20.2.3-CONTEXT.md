## CI Failures (fix first — most mechanical)

### SERV-01 — Server startup test fails in CI (`tests/server.test.ts:43`)
The test spawns `bun run src/server.ts` and polls :4219 for up to 25s. Fails consistently on all 3 platforms. Was previously fixed in commit `1b5e6a1`. The squash includes that fix, so something in the CI environment is different. Root cause unclear without deeper investigation. **Approach:** investigate subprocess startup, ensure the server can actually start, or if it's a flaky integration test mark with environment guard.

### git/log test — Returns 0 commits (`tests/dialog-api.test.ts:115`)
`getGitLog` filters commits to `^(docs|feat|fix|refactor|test|chore)\(`. The CI checkout uses `actions/checkout@v4` at default depth=1, which may only expose the auto-generated merge commit (subject: "Merge pull request #1500...") which fails the filter. **Fix:** add `fetch-depth: 0` to checkout in `.github/workflows/pr-check.yml` so full git history is available.

### Pipeline timeouts — 2 tests time out at 5000ms (`tests/pipeline-perf.test.ts:104,136`)
These tests start a real pipeline and WebSocket server, wait for initial state message, then trigger a file write and wait for a diff broadcast. CI is slower than local, and the 5000ms default Bun test timeout is too tight. **Fix:** add `{ timeout: 15000 }` to these two test cases.

## Security Findings — Required Before Merge

Review by @glittercowboy (CHANGES_REQUESTED on PR #1500).

### CRITICAL

**C1 + C2 — `validatePath` called without `allowedRoot` in `fs-api.ts`**
- `/api/fs/list` and `/api/fs/detect-project` call `listDirectory(dirPath)` which calls `resolve(dirPath)` without any root restriction — any caller can enumerate `~/.ssh/`, `/etc/`, etc.
- `/api/fs/mkdir` calls `validatePath(body.path)` without `allowedRoot`
- **Context:** These are intentional for the project-picker (user browsing their filesystem). Localhost-only server is the primary defense.
- **Fix:** This is a design intent issue. For `mkdir`, the caller is the app itself creating a project directory — restrict to user's home dir. For `list` and `detect-project`, the browsing design is intentional but needs an explicit comment explaining the accepted threat model, consistent with the WS SECURITY NOTE pattern from 20.2.1.

**C3 — Trust endpoint `body.dir` unvalidated (`trust-api.ts`)**
- `POST /api/trust` accepts `body.dir` from the client and calls `mkdir(gsdDir, { recursive: true })` + `writeFile(...)` with no validation.
- An attacker could create arbitrary directories and write trust flags anywhere.
- **Fix:** Validate that `body.dir` is an absolute path and ends with `/.gsd` (or contains `/.gsd/`). Reject anything that doesn't look like a GSD project's `.gsd` directory.

**C4 — SSRF via proxy — port unvalidated (`proxy-api.ts`)**
- `handleProxyRequest(req, url, port)` — `port` comes from `searchParams.get("port")` in server.ts. Any value goes through to `fetch(http://localhost:${port}...)`, potentially hitting internal services.
- **Fix:** Validate port is in range 1024–65535 before proxying. Also strip `Authorization` and `Cookie` headers from the forwarded request to prevent auth token leakage.

**C5 — `assetScope: { allow: ["**"] }` too permissive (`tauri.conf.json`)**
- The `asset://` protocol can read every file on disk. XSS in the webview = arbitrary file read.
- **Fix:** Restrict to app resource directory: `"allow": ["$RESOURCE/**", "$APP/**"]`.

### HIGH (Required Before Merge per review)

**H1 — `capabilities.json` is `{}` — all IPC commands exposed to all windows**
- Without capability definitions, all invoke_handler commands (`set_credential`, `restart_bun`, shell plugin) are accessible from any window.
- **Fix:** Create a proper capabilities file at `src-tauri/capabilities/main.json` defining which windows can call which commands.

**H2 — `tauri-plugin-shell` initialized with no restrictions**
- Shell plugin is initialized in `lib.rs` but no Rust commands use it. With empty capabilities, frontend JS may have `shell:execute` access.
- **Fix:** Either remove `tauri-plugin-shell` from `Cargo.toml` and `lib.rs` (preferred if unused), or add explicit capability restrictions.

**H6 — Static file serving path traversal (`server.ts`)**
```typescript
const filePath = resolve(import.meta.dir, "../public", pathname.slice(1));
```
No traversal check. `GET /../../etc/passwd` would resolve outside `public/`.
- **Fix:** After resolving, check that `filePath.startsWith(publicDir)` before serving.

**H7 — Git status `root` param unvalidated (`git-api.ts`)**
- `searchParams.get("root")` passed directly to `git status --porcelain`. Allows probing arbitrary directories.
- **Fix:** Validate that `root` is an absolute path (reject relative). The `getGitStatus` function already calls `resolve(root)` but doesn't restrict it further. Add a check that the root exists and is a directory. Document the accepted browsing threat model.

**H8 — `tauri-apps/tauri-action@v0` floating tag (`release.yml:77`)**
- Has access to Apple signing certs, GPG key, and Tauri signing key. Should be pinned to SHA.
- **Fix:** Pin to a specific SHA commit of `tauri-apps/tauri-action`.

### Medium (Should Fix)

**M — `Math.random()` for auth session IDs (`auth-api.ts:130`)**
- `Math.random().toString(36).slice(2) + Math.random().toString(36).slice(2)` is predictable.
- **Fix:** Replace with `crypto.randomUUID()`.

**M12 — Window close kills Bun for all windows (`lib.rs:62-71`)**
- `on_window_event` kills Bun on every window Destroyed event, not just the last one.
- **Fix:** Only kill Bun when `app_handle.webview_windows().is_empty()` after the window is gone.

**H5 — `skipPermissions` hardcoded to `true` (`pipeline.ts`/`claude-process.ts`)**
- `--dangerously-skip-permissions` always passed. No permission guardrails.
- **Fix:** Read from project settings; default to `false`. (Bigger change — do it but scope carefully.)

## Locked Decisions

- **C1/C2 browsing design is intentional** — the filesystem browser needs full access. Mitigation is localhost-only server + SECURITY NOTE comment (follow the WS pattern from 20.2.1). No `allowedRoot` restriction on list/detect-project.
- **H3/H4 (no HTTP/WS auth)** — accepted threat model per review comment on PR #1259 (S5 already addressed). Add SECURITY NOTE in server.ts consistent with ws-server.ts.
- **`tauri-plugin-shell` removal** — preferred over adding capability restrictions (simpler; it's not used anywhere in the Rust commands).
