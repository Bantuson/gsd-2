# Phase 20.2.6 Plan 01: Post-Audit Security Remediation — 4 Surgical Fixes Summary

## What Was Done

### Task 1: FS-9 + API-6 (kill-port.ts + server.ts)

**FS-9** — `kill-port.ts` line 23: `/s+/` changed to `/\s+/`. The broken regex matched literal `s` characters, not whitespace. On Windows, `netstat -ano` output is whitespace-delimited so all PID extractions returned `NaN` and were filtered out — the kill step silently no-oped. The fix makes Windows port recycling work as intended.

**API-6** — `server.ts` line 129: condition changed from `if (host && !ALLOWED_HOSTS.has(host))` to `if (!host || !ALLOWED_HOSTS.has(host))`. The original let null/undefined Host values pass through (HTTP/1.0 clients, raw `curl --http1.0`). The fix ensures missing Host is rejected the same as an invalid one.

### Task 2: API-4 (server.ts)

The `/api/trust` POST handler in `server.ts` called `writeTrustFlag(gsdDir)` with no path validation, allowing authenticated callers to write a trust flag file at an arbitrary filesystem path. Added the same validation used in `trust-api.ts`'s `registerTrustRoutes`: normalize backslashes, check `endsWith("/.gsd")` and `includes("/.gsd/")`, return 400 with `"dir must be a .gsd directory path"` on failure. `writeTrustFlag` is only reached after the guard passes.

### Task 3: FE-5/FE-6 (CodeExplorer.tsx + InlineReadPanel.tsx)

Both components had `import DOMPurify from "dompurify"` and called `DOMPurify.sanitize()` with no configuration, bypassing the `sanitize-html.ts` allowlist wrapper added in phase 20.2.5. Removed the direct `DOMPurify` import (and the comment containing "DOMPurify") from both files. Replaced each `DOMPurify.sanitize(...)` call with `sanitizeHtml(...)` — a drop-in replacement. Both components already had the `sanitizeHtml` import; no new import lines were needed.
