**Gathered:** 2026-03-23

<domain>
## Phase Boundary

This phase delivers complete security hardening for Mission Control across all 7 threat categories identified in the threat model. The contract is: every one of the 81 required secure behaviours MUST have a passing Nyquist test, and every one of the 74 findings MUST be fully remediated — both server-side AND the corresponding TypeScript caller where applicable. No accepted risks. No half-implementations.

**In scope:**
- T-FILE: 15 findings (FS-01 through FS-15) — path traversal, file write, symlink escape
- T-EXEC: 6 findings (TAURI-02, TAURI-03, TAURI-12, NET-15, XSS-01, XSS-02) — RCE via PATH hijack, XSS→IPC chain
- T-NET: 16 findings (NET-01 through NET-16) — SSRF, DNS rebinding, DoS resource exhaustion
- T-AUTH: 14 findings (AUTH-01 through AUTH-14) — unauthenticated APIs, OAuth bypass
- T-XSS: 13 findings (XSS-01 through XSS-07, CSP-01 through CSP-02, URL-01, TAURI-10, TAURI-11) — injection into WebView
- T-DOS: 9 findings (NET-02, NET-03, NET-06, NET-07, NET-16, AUTH-07, AUTH-08, TAURI-06, TAURI-07, TAURI-08, DATA-01) — runtime panics, blocking calls
- T-CRED: 7 findings (AUTH-09, NET-14, TAURI-01, TRUST-01, AUTH-04, FETCH-01, TAURI-13, TAURI-15) — credential theft

**Out of scope:** New features, UI changes unrelated to security, performance optimisations not tied to DoS hardening.

</domain>

<decisions>
## Implementation Decisions

All decisions below are LOCKED. They are derived directly from the threat model's required controls. The executor MUST NOT deviate from these without a documented threat model change.

### METHODOLOGY (LOCKED)
- Write Nyquist tests FIRST (red) for each required secure behaviour, then implement fixes to make them green. Tests MUST be behaviour-validating (assert what the code does), not string-presence checks (assert that a string exists in source).
- Every fix MUST be complete end-to-end: if a Rust IPC signature changes, the TypeScript caller MUST be updated in the same plan. No partial implementations.
- Re-run all 5 domain audits (FS, NET, TAURI, AUTH, XSS) after implementation to verify no new findings were introduced.

### T-FILE: PATH VALIDATION (LOCKED)
- `validatePath(input, root)` MUST call `fs.realpathSync(resolved)` and compare against `root + path.sep` (with trailing separator) — not `root` alone.
- `validatePath` MUST reject symlinks that escape the workspace root.
- `validatePath` MUST reject paths containing `..`, null bytes, or path separators in user-supplied components.
- All HTTP response bodies MUST be scrubbed of absolute filesystem paths.
- All HTTP error messages MUST NOT include OS error strings containing filesystem paths.
- `sliceId`, `milestoneId`, `taskId`, `sessionSlug`, `file.name` (multipart) MUST be sanitized before path construction; use `path.basename()` for filenames.
- `removeSessionWorktree` MUST verify resolved path is within workspace root before calling `rm -rf`.
- All files created by the application MUST use mode `0o600`; `~/.gsd/auth.json` MUST be created and corrected to `0600` on startup.

### T-EXEC: PROCESS SPAWNING (LOCKED)
- Bun MUST be spawned using the absolute verified path to the binary, NOT the bare name `"bun"` or `"bun.exe"`.
- The child process environment MUST be an explicit allowlist (`HOME`, `PATH` with fixed value, `LANG`) — NOT a clone of the parent environment.
- `NODE_OPTIONS`, `LD_PRELOAD`, `DYLD_INSERT_LIBRARIES`, `HTTP_PROXY`, `HTTPS_PROXY` MUST be stripped from child env.
- `kill-port.ts` MUST use `execFile` with port as separate argument, NOT string interpolation in `execSync`.
- `git-api.ts` MUST use `execFile()` with argument arrays for all git invocations.
- `dep_check` MUST verify binary path against known installation directory.

### T-NET: NETWORK HARDENING (LOCKED)
- HTTP server MUST validate `Host` header equals `127.0.0.1:4200`; reject anything else with HTTP 400.
- WebSocket upgrades MUST validate `Origin` header matches `file://` or `tauri://localhost`; reject all others with HTTP 403.
- Proxy MUST allowlist destination hosts (AI provider hostnames only) and ports (443 only); reject all other destinations with HTTP 403.
- Proxy MUST strip `X-Forwarded-For`, `X-Forwarded-Host` from client requests before forwarding.
- Proxy MUST preserve `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options` from upstream responses.
- HTTP server MUST reject bodies exceeding 10 MB with HTTP 413.
- NDJSON parser MUST cap individual line at 1 MB; close stream on exceed.
- Screenshot/image data MUST be rejected if base64-decoded size exceeds 5 MB.

### T-AUTH: AUTHENTICATION (LOCKED)
- All HTTP endpoints MUST require a per-launch secret token (generated with `crypto.randomUUID()`); missing/invalid token → HTTP 401.
- All WS upgrade requests MUST present the per-launch token; reject without it.
- Window IDs MUST use `crypto.randomUUID()`, not `Math.random()`.
- Auth session map MUST cap at 100 concurrent sessions; additional creation → HTTP 429.
- All HTTP endpoints MUST enforce rate limiting; exceed → HTTP 429.
- Session ownership check: WS client for session A MUST NOT access session B data.
- CORS: reject `Origin` headers not matching `tauri://localhost`, `file://`, or absent.

### T-XSS + T-CRED: CONTENT SECURITY (LOCKED)
- ALL markdown output rendered in the WebView MUST pass through `DOMPurify.sanitize()` before `dangerouslySetInnerHTML` assignment.
- CSP MUST NOT contain `'unsafe-inline'` in `script-src`; MUST use nonces or hashes.
- CSP `connect-src` MUST enumerate specific AI provider origins, not wildcard `ws://127.0.0.1:*`.
- All preview iframes MUST have a `sandbox` attribute; `allow-same-origin` + `allow-scripts` together is forbidden unless documented.
- `OAuthConnectFlow.tsx` MUST validate external URLs begin with `https://` before calling `open_external`.
- `open_external` MUST encode URLs via URL parser before OS call.
- `file://` URLs MUST use `new URL('file://')` with path encoding.
- A capability file MUST exist per secondary window type; each file MUST list only commands that window requires.
- Only the main window MUST have `set_credential`, `delete_credential`, `get_credential` capabilities.
- Trust check MUST fail closed on network error (treat workspace as untrusted).
- Writing the trust flag MUST require explicit user dialog confirmation.
- Token refresh MUST use mutex to prevent concurrent concurrent refresh for same credential.
- Auth errors MUST use a single generic message; no leaking of expired/invalid/missing state.
- Logout MUST invoke `clear_all_credentials` and verify all tokens removed before returning success.
- OAuth deep link MUST reject URLs > 2048 chars and MUST validate `state` nonce before accepting code.
- Authorization codes MUST be bound to the session that initiated the OAuth flow.

### T-DOS: RUST SAFETY (LOCKED)
- ZERO `.unwrap()` calls on `Mutex::lock()` results in the main Tauri process; ALL MUST handle `PoisonError`.
- `child.wait()` MUST be inside `tokio::task::spawn_blocking`.
- `pick_folder` and all file-picker calls MUST use `spawn_blocking` or async Tauri dialog plugin variant.
- Port allocation for WS servers MUST use atomic bind-and-hold; bound socket passed directly to WS server constructor.
- Window registration pool MUST cap at 10; 11th registration MUST return error, not hang.

### Claude's Discretion
- Order of implementation within each threat category (prioritize HIGH first, then MEDIUM, then LOW within each category)
- Specific test file naming conventions and structure (follow existing Nyquist patterns in src-tauri/tests/ and TS test directories)
- Whether to create a single large test file per threat category or split by finding ID
- Exact rate limiting strategy implementation (token bucket vs sliding window — pick simplest that works)

</decisions>

<specifics>
## Specific Requirements

### The 81 Required Secure Behaviours
All 81 behaviours are in `.planning/THREAT-MODEL.md`. They are numbered 1–81 and grouped by threat entry. Each behaviour maps to a Nyquist test. The test MUST:
- Assert behaviour (e.g., HTTP 400 returned, file NOT read), not string presence
- Be runnable in isolation (not depend on a running server unless explicitly an integration test)
- Cover both the happy path (legitimate request passes) and the attack path (malicious request blocked)

### Severity Distribution (implementation priority)
- **9 HIGH** — FS-01, FS-02, FS-03, NET-01, TAURI-01, TAURI-02, TAURI-03, XSS-01, XSS-02 → implement first
- **28 MEDIUM** — implement second
- **36 LOW** — implement third

### Half-implementation prevention rule
For every Rust IPC signature change:
1. The PLAN.md that changes the Rust signature MUST list the TypeScript `invoke()` call in its `files_modified` and `acceptance_criteria`
2. The executor MUST NOT mark the plan complete until both layers pass the Nyquist test

</specifics>

<deferred>
## Deferred Items

- Localhost TLS (AUTH-03 / API-01 note about plaintext localhost HTTP): accepted as known limitation of Tauri architecture; full TLS on loopback requires OS-level configuration. Mitigated by per-launch token auth.
- Updater signing key CI verification (TAURI-15): deferred to a dedicated CI/CD phase; not part of the desktop application code.
- Multi-user system `~/.gsd/auth.json` world-read concern beyond `0600`: correct permissions address this on POSIX; Windows ACL equivalent tracked as separate concern.

</deferred>
