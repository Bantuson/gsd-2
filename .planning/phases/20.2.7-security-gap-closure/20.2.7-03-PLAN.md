After the existing B23 section (the last accepted risk entry), add 4 new sections with horizontal rule separators between them:

Section A: `### GAP-2 -- /api/fs/list Full Filesystem Enumeration (ACCEPTED)`
- Status: Accepted risk
- Date: 2026-03-25
- Behaviour: The /api/fs/list endpoint allows browsing the entire filesystem, not just the home directory.
- Rationale: Intentional UX design -- project picker requires full FS browsing. Protected by B50 launch token.
- Mitigations: B50 (launch token), B37 (host validation for 127.0.0.1:4200 and localhost:4200), B38 (WS origin validation), read-only endpoint
- Residual risk: Local process with token could enumerate FS -- equivalent to calling readdir() directly.

Section B: `### GAP-3 -- WebSocket Token in URL Query String (HISTORICAL)`
- Status: Resolved in phase 20.2.7
- Date: 2026-03-25
- Behaviour: Prior to 20.2.7, WS launch token passed as ?token=value in URL query string.
- Resolution: Replaced with first-message handshake pattern. Client sends { type: "auth", token: "..." } as first WS message. Server holds UNAUTHENTICATED until valid auth; closes 4001 after 5-second timeout.

Section C: `### GAP-9 -- Rate Limiter Single Global Bucket (ACCEPTED)`
- Status: Accepted risk
- Date: 2026-03-25
- Behaviour: Rate limiter (B44) uses single global bucket, not per-client.
- Rationale: All localhost traffic from 127.0.0.1 -- per-client bucketing impossible. 100 req/s cap intentional.
- Mitigations: B44 rate limit, single-user app, localhost-only
- Residual risk: None meaningful.

Section D: `### localhost:4200 DNS Rebinding Surface (ACCEPTED)`
- Status: Accepted risk
- Date: 2026-03-25
- Behaviour: ALLOWED_HOSTS includes localhost:4200 alongside 127.0.0.1:4200. localhost resolves via DNS.
- Rationale: Both entries needed for cross-platform compat (Windows uses localhost).
- Mitigations: B50 (token required), B55 (origin validation), B38 (WS origin validation)
- Residual risk: DNS rebinding + token compromise needed -- token is the true guard.
