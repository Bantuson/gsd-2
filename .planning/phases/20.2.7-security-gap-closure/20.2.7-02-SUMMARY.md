# Phase 20.2.7 Plan 02: WS First-Message Auth Handshake Summary

**One-liner:** Replaced WebSocket URL query-string token auth with first-message handshake — token moves from URL (visible in network tab/proxy logs) to first WS message body, with 5-second unauthenticated connection timeout (close 4001).

## What Was Done

### Task 1 — WS first-message auth handshake implementation (server + client)

**ws-server.ts (server-side):**
- Removed URL token validation from the `fetch` handler (lines that read `?token=`)
- Changed `server.upgrade()` to set `authenticated: !launchToken` in connection data
- Replaced the `open` handler: when `launchToken` is set, connection starts UNAUTHENTICATED, sets a 5-second timeout that closes with 4001 if not authenticated; when no `launchToken`, auto-authenticates immediately (backward compat)
- Added auth message handling at the TOP of `message` handler: parses `{ type: "auth", token }`, validates token, subscribes to topics, sends full state, calls `onClientConnect`; closes with 4001 on invalid token or non-JSON
- Updated `close` handler to clear the auth timeout on disconnect

**window-identity.ts (token source for client hooks):**
- Added `export let launchToken = ""` and `export function setLaunchToken(token: string): void`
- Extended `initWindowIdentity()` to fetch `/api/auth/startup-token` after window registration, storing the token in the module-level `launchToken` variable

**useReconnectingWebSocket.ts (primary WS hook):**
- Added `import { launchToken } from "../window-identity"`
- Modified `ws.onopen` to send `JSON.stringify({ type: "auth", token: launchToken })` as first message when token is set

**useChatMode.tsx and usePreview.ts (direct WebSocket consumers):**
- Both hooks create `new WebSocket(wsUrl)` directly without going through `useReconnectingWebSocket`
- Added `import { launchToken } from "@/window-identity"` / `"../window-identity"`
- Added `ws.addEventListener("open", ...)` / `ws.onopen` handlers that send auth message as first message

### Task 2 — WS handshake regression tests

Created `tests/security-ws-handshake.test.ts` with 6 test cases:

| Test | Assertion |
|------|-----------|
| valid auth message | connection receives `{ type: "full" }` state after auth |
| invalid token | close code 4001 |
| auth timeout (~5s) | close code 4001, elapsed 4–7.5 seconds |
| no state before auth | only 1 full-state message, arrives after auth sent |
| no launchToken | auto-authenticates, state arrives immediately |
| post-auth chat | `onChatMessage` callback fires after authenticated |

All 6 tests pass. Existing ws-server.test.ts (11 tests) still pass — backward compat confirmed.

## Deviations from Plan

### Auto-fix: useChatMode.tsx and usePreview.ts also updated

**Found during:** Task 1 code reading
**Issue:** `useChatMode.tsx` and `usePreview.ts` create raw `new WebSocket(wsUrl)` directly, bypassing `useReconnectingWebSocket`. Without auth message on open, these connections would hang unauthenticated and be closed with 4001 after 5 seconds.
**Fix:** Added `launchToken` import and `ws.onopen`/`ws.addEventListener("open")` handlers to both hooks that send the auth message as first message.
**Rule:** Rule 2 (missing critical functionality for correct operation)
**Files modified:** `useChatMode.tsx`, `usePreview.ts`
