## Accomplishments

- pipeline.ts intercepts `browser_state_update` events before generic chat_event forwarding, broadcasts via publishChat to all clients, and signals the preview panel to auto-open
- usePreview hook manages `browserScreenshot` state from WS messages with 10-second auto-clear timer to return to iframe mode when browser activity stops
- PreviewPanel renders base64 JPEG screenshots with a URL bar (amber pulse indicator + URL + title) and "Browser Agent" amber badge in the header
- Auto-toggle works: screenshot view takes full priority over all viewport modes (desktop/tablet/mobile/dual), returns to iframe after 10s of inactivity

## Decisions Made

- `browser_state_update` intercepted with `return;` to prevent large base64 JPEG data from polluting the chat transcript stream — screenshots go exclusively through the publishChat broadcast channel
- `preview_open` with `port: 0` as a "panel open only" signal — guard `data.port > 0` before `addManualPort` prevents adding a server entry for port 0
- `DetectedServer.label` reverted to optional (`label?`) to fix test contract mismatch — the interface originally had `label?:` but was changed to required in a previous plan; all call sites already use `s.label ?? ...` fallback pattern
- `scanForDevServers` refactored from type predicate filter to for-loop to eliminate TS2677/TS2339 TypeScript errors that were pre-existing
