**OAuthConnectFlow.tsx — Add validateOAuthUrl and apply it:**
Read OAuthConnectFlow.tsx. Find where it calls the Tauri `open_external` command (or
`open` or equivalent). Add validation before the call:

```typescript
/**
 * Validates that a URL is safe to open externally.
 * SECURITY (B68): Only https:// URLs are permitted.
 * This prevents javascript:, data:, and other dangerous schemes from reaching the OS.
 *
 * @export — exported for testing in security-txss.test.ts
 */
export function validateOAuthUrl(url: string): boolean {
  if (!url || typeof url !== "string") return false;
  try {
    const parsed = new URL(url);
    return parsed.protocol === "https:";
  } catch {
    return false;
  }
}

// In the OAuth flow handler, before calling open_external:
if (!validateOAuthUrl(authUrl)) {
  console.error("[OAuthConnectFlow] Rejected non-https URL:", authUrl);
  setError("Invalid authentication URL");
  return;
}

// Now safe to open:
await invoke("open_external", { url: authUrl });
```

**commands.rs — Use Url::parse() in open_external (B69, B70):**
Find the `open_external` Tauri command. Update it to validate via Rust's URL parser:

```rust
use url::Url;

#[tauri::command]
pub async fn open_external(url: String) -> Result<(), String> {
    // B69: Validate URL via parser — reject malformed or dangerous URLs
    let parsed = Url::parse(&url).map_err(|e| {
        eprintln!("[open_external] Invalid URL rejected: {e}");
        "Invalid URL".to_string()
    })?;

    // B68: Only allow https:// scheme (frontend should also check, but defense in depth)
    if parsed.scheme() != "https" {
        eprintln!("[open_external] Rejected non-https scheme: {}", parsed.scheme());
        return Err("Only https:// URLs may be opened externally".to_string());
    }

    // Use the re-serialized URL from the parser (not the raw input string)
    // This prevents parser differential attacks
    let safe_url = parsed.to_string();

    // Open via the OS shell using the validated, re-serialized URL
    tauri::api::shell::open(&app_handle.shell(), safe_url, None)
        .map_err(|e| format!("Failed to open URL: {e}"))
}
```

Adjust the exact API call based on the Tauri 2.x shell plugin API.
The key security property: use `parsed.to_string()` (the re-serialized URL from the URL parser),
NOT the original `url` string.

  <action>
Read auth-api.ts. Find the token refresh hook — this is the code that refreshes OAuth tokens
when they expire. The audit identified a race condition: concurrent refresh calls can result
in double-use of refresh tokens.

**Add a per-credential refresh mutex using a simple Map-based lock:**
```typescript
// T-AUTH-02 B64: Mutex to prevent concurrent token refresh for the same credential
const refreshLocks = new Map<string, Promise<void>>();

async function withRefreshLock<T>(credentialKey: string, fn: () => Promise<T>): Promise<T> {
  // Wait for any existing refresh to complete
  const existing = refreshLocks.get(credentialKey);
  if (existing) {
    await existing;
    // After the existing refresh completes, the new token should be available
    // Return early — the caller can re-read the credential
  }

  let resolve!: () => void;
  const lock = new Promise<void>(r => { resolve = r; });
  refreshLocks.set(credentialKey, lock);

  try {
    return await fn();
  } finally {
    resolve();
    refreshLocks.delete(credentialKey);
  }
}
```

**Apply to the token refresh call site:**
```typescript
// BEFORE (race condition — B64 violation):
async function refreshToken(provider: string): Promise<string> {
  const newToken = await callRefreshEndpoint(provider);
  await storeToken(provider, newToken);
  return newToken;
}

// AFTER (B64: mutex prevents concurrent refresh):
async function refreshToken(provider: string): Promise<string> {
  return withRefreshLock(provider, async () => {
    const newToken = await callRefreshEndpoint(provider);
    await storeToken(provider, newToken);
    return newToken;
  });
}
```

If the token refresh is implemented differently (e.g., using a flag or debounce), apply the
same mutex concept using the `withRefreshLock` wrapper.

The mutex ensures that if two requests trigger a refresh simultaneously, the second one waits
for the first to complete rather than issuing a second refresh request.
