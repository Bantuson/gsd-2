# Phase 20.2.5 Plan 06: sessionSlug validation, path containment, and NDJSON stream close Summary

## One-Liner

Added VALID_SLUG_RE validation and realpathSync path containment checks to worktree-api.ts (B13/B14), registered worktree HTTP routes in server.ts, and changed ndjson-parser to throw instead of silently drop on 1MB+ lines (B42).

## What Was Built

### Task 1: sessionSlug validation and path containment in worktree-api.ts (B13, B14)

**validateSlug() function added to worktree-api.ts:**
- Allowlist regex: `/^[a-zA-Z0-9_-]+$/` — only alphanumeric, hyphen, underscore
- Explicit rejection of: null bytes (`\x00`), `..` sequences, `/` and `\` path separators
- Applied to `createSessionWorktree`, `renameSessionWorktree` (both old and new slug)

**Path containment check in removeSessionWorktree (B14):**
- Uses `realpathSync(repoRoot)` to resolve the repository root
- Uses `realpathSync(worktreePath)` to resolve the worktree path (follows symlinks)
- Falls back to `pathResolve(worktreePath)` if worktree path doesn't exist yet
- Checks `resolvedWorktreePath.startsWith(resolvedRepoRoot + sep)` — the `sep` suffix prevents the sibling-prefix bypass (e.g., `/workspace-evil` starting with `/workspace`)
- Returns `{ ok: false, error: "Invalid worktree path" }` on failure — no git commands executed

**Routes registered in server.ts:**
- `POST /api/worktree/create` — validates sessionSlug, calls createSessionWorktree
- `DELETE /api/worktree/session` — validates sessionSlug, calls removeSessionWorktree
- Both return HTTP 400 with `{ error: "Invalid session slug" }` on traversal attempts (vs previous 404)

### Task 2: NDJSON parser throws on oversized line (B42)

The `createNdjsonParser` function previously silently dropped lines exceeding MAX_LINE_LENGTH (1,048,576 bytes). The B42 test expects the parser to **throw** on such lines.

Three throw points added:
1. **Buffer overflow without newline** — when `buffer.length > MAX_LINE_LENGTH && !buffer.includes("\n")`, buffer cleared and Error thrown
2. **Completed line too long** — when a split line's length exceeds MAX_LINE_LENGTH, buffer cleared and Error thrown
3. **Oversized final flush** — in `flush()`, if the remaining buffer exceeds MAX_LINE_LENGTH, Error thrown

All 13 pre-existing `ndjson-parser.test.ts` unit tests continue to pass.
