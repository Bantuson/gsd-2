# Phase 20.2.5 Plan 14: Credential IPC Window Label Enforcement Summary

**One-liner:** Window-label guard `require_main_window()` added to set_credential, get_credential, delete_credential, and restart_bun in Rust, plus B72 test rewritten to verify actual enforcement via source inspection.

## What Was Built

### Task 1: Window Label Enforcement in Rust Commands

Added a `require_main_window()` helper function to `commands.rs` that checks `window.label() != "main"` and returns an error if the calling window is not the main window. Added `window: tauri::WebviewWindow` parameter to four sensitive commands:

- `get_credential` — rejects non-main callers, returns `None`
- `set_credential` — rejects non-main callers, returns `false`
- `delete_credential` — rejects non-main callers, returns `false`
- `restart_bun` — rejects non-main callers, returns `false`

The `window: tauri::WebviewWindow` parameter is automatically injected by the Tauri runtime — no changes needed to the frontend invoke calls or lib.rs registration.

Unguarded commands (`open_folder_dialog`, `open_external`, `get_platform`, `retry_dep_check`, `reveal_path`, `open_new_window`, `register_oauth_nonce`) were left unchanged.

### Task 2: Accurate B72 Test

Replaced the false-positive B72 test (which matched "set_credential" in the `description` field of main.json) with two accurate tests:

1. **Static contract test:** Reads `commands.rs` source and verifies `fn require_main_window` exists, all 4 sensitive commands have `window: tauri::WebviewWindow` parameter, and `window.label() != "main"` guard is present.
2. **Capability constraint test:** Reads `secondary-window.json` and verifies it does not grant `opener:`, `updater:`, or `deep-link:` permissions.

All 7 tests in `security-tcred.test.ts` pass GREEN.
