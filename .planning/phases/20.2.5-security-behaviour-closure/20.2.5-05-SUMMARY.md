# Phase 20.2.5 Plan 05: API Input Validation — T-FILE Closure Summary

**One-liner:** Per-API validateSegment() input validation on sliceId/milestoneId/taskId/projectName + basename/containment on uploads closes B1-B3, B7, B9-B12.

## Objective

Sanitize all API input parameters in the four file-operation APIs that accept user-controlled path segments. Plan 04 fixed the underlying `validatePath` function — this plan applies input validation at each API entry point before path construction.

## Tasks Completed

### Task 1: Add validateSegment helper and sanitize gsd-file-api.ts inputs (B1, B2, B3, B7)

Added `validateSegment(segment, label)` function to `gsd-file-api.ts` that:
- Rejects null bytes (`\x00`)
- Rejects traversal sequences (`..`)
- Rejects path separators (`/` and `\`)
- Throws `Error("Invalid path segment")` on violation

Applied to:
- `sliceId` parameter — validated before any `join()` call (B1)
- `milestoneId` parameter — validated when non-empty before `join()` call (B2)
- `taskId` parameter — validated before passing to `resolveTaskId()` (B3)

All catch blocks return `{ error: "Invalid request parameters" }` or `{ error: "File operation failed" }` — no `err.message` leaks (B7).

**Commit:** `d6c8c5dc` feat(20.2.5-05): add validateSegment to gsd-file-api — close B1 B2 B3 B7

### Task 2: Sanitize uat-results-api, assets-api, workspace-api inputs (B9, B10, B11, B12)

**uat-results-api.ts:**
- Added copy of `validateSegment()` function
- Validates `sliceId` before `join(gsdDir, sliceId + "-UAT-RESULTS.md")` write path (B9)
- Replaced `err.message` in 500 response with generic `"Write failed"` message

**assets-api.ts:**
- Applied `path.basename(file.name)` to sanitize uploaded filename before path construction (B10)
- Added early rejection for filenames containing traversal sequences after basename (defense in depth)
- Imported `validatePath` from `./fs-api` and added containment check after path construction (B11)
- Added `{ mode: 0o600 }` to `Bun.write()` call for uploaded files
- Replaced `err.message` in DELETE 500 response with `"File operation failed"`

**workspace-api.ts:**
- Added `validateProjectName(name)` rejecting `..`, `/`, `\`, `\x00` (B12)
- Validates project name before `createProject()` call
- Replaced `err.message` leaks in error responses with generic messages

**Commit:** `e8d7d7d2` feat(20.2.5-05): sanitize uat-results, assets, workspace API inputs — close B9 B10 B11 B12
