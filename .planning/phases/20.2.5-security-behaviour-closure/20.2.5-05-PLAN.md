Sanitize all API input parameters in the four file-operation APIs that accept user-controlled
path segments. Plan 04 fixed the underlying validatePath function — this plan applies input
validation at each API entry point before path construction.

The core pattern for each API:
1. Extract the path segment from request params/body
2. Call validateSegment() — rejects null bytes, traversal sequences, path separators
3. Build the full path
4. Call validatePath() from fs-api.ts to confirm the resolved path stays within workspace

Read gsd-file-api.ts first. Add a `validateSegment` function near the top of the file:

```typescript
import path from "node:path";

/**
 * Validates a single path segment (e.g., sliceId, milestoneId, taskId).
 * Rejects traversal sequences, path separators, and null bytes.
 * Returns the segment unchanged if valid.
 */
function validateSegment(segment: string, label: string): string {
  if (!segment || typeof segment !== "string") {
    throw new Error("Invalid path segment");
  }
  // Reject null bytes
  if (segment.includes("\x00")) {
    throw new Error("Invalid path segment");
  }
  // Reject traversal sequences
  if (segment.includes("..")) {
    throw new Error("Invalid path segment");
  }
  // Reject path separators (prevents multi-segment injection)
  if (segment.includes("/") || segment.includes("\\")) {
    throw new Error("Invalid path segment");
  }
  return segment;
}
```

Apply `validateSegment` to EVERY route handler that uses `sliceId`, `milestoneId`, or `taskId`
in a path construction call. Pattern:

Before:
```typescript
const slicePath = path.join(gsdDir, milestoneId, sliceId + ".md");
```

After:
```typescript
const validSliceId = validateSegment(sliceId, "sliceId");
const validMilestoneId = validateSegment(milestoneId, "milestoneId");
const slicePath = path.join(gsdDir, validMilestoneId, validSliceId + ".md");
```

For each route, add early return on validation failure:
```typescript
try {
  validateSegment(sliceId, "sliceId");
} catch {
  return Response.json({ error: "Invalid request parameters" }, { status: 400 });
}
```

Strip absolute paths from ALL catch blocks:
- Replace `{ error: err.message }` with `{ error: "File operation failed" }` in 500 responses
- Replace `{ error: err.message }` with `{ error: "Invalid request parameters" }` in 400 responses
- Log original errors: `console.error("[gsd-file-api] error:", err)`

Do NOT use validatePath from fs-api.ts for segment validation — validateSegment is simpler
and runs before path construction. validatePath runs after construction as a second layer.
