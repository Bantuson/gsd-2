# Phase 20.2.5 Plan 15: Credential Lifecycle Gap Closure Summary

**One-liner:** Frontend logout clears OS keychain via Tauri IPC invoke('delete_credential') with provider-scoped key selection, plus THREAT-MODEL.md formalizing accepted risks for B57/B71 (plaintext auth.json) and B23 (dep_check warning-only).

## What Was Built

### Task 1 — Keychain cleanup in frontend logout (B62)

Modified `packages/mission-control/src/auth/auth-api.ts`:

- Added `KEYCHAIN_CREDENTIAL_KEYS` constant (5 keys matching ALLOWED_CREDENTIAL_KEYS in commands.rs)
- Added `keychainKeysForProvider()` helper: full-logout clears all 5 keys; provider-scoped logout clears only that provider's keys
- Modified `changeProvider()` to call `invoke("delete_credential", { key })` for each relevant key after server-side logout succeeds
- Used `Promise.allSettled` (not `Promise.all`) so individual key deletion failures don't abort the cleanup
- Wrapped Tauri IPC import in try/catch so browser dev mode works without errors

### Task 2 — Risk acceptance documentation (B57/B71, B23)

Created `.planning/THREAT-MODEL.md` with "## Accepted Risks and Mitigations" section:

- **B57/B71:** Documents why plaintext auth.json is accepted — Bun HTTP server is a child process without access to Tauri IPC bridge. Lists compensating controls: B16/B58 (0o600 permissions), B50 (per-launch token), B37 (host validation)
- **B23:** Documents dep_check warning-only behavior as intentional design — absolute canonicalized path (resolve_bun_path) prevents PATH hijack regardless. B19/B20/B21 enumerated as compensating controls.
