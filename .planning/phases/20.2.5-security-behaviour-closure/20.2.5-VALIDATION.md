## Audit Trail

### GAP 1 — B16 (security-tfile.test.ts)

**Problem:** `existsSync` guard meant CI always hit the `expect(true).toBe(true)` branch since `~/.gsd/auth.json` is absent in CI.

**Fix approach:** Platform-split fixture test. On POSIX, creates a temporary file with `{ mode: 0o600 }` and verifies `statSync().mode & 0o777 === 0o600`. On Windows, returns early with an inline comment explaining NTFS ACL semantics.

**Test type:** Unit (filesystem fixture)

**Verification:** Ran on Windows — test returns early (platform skip path), no false positive. Would pass on Linux/macOS via the fixture path.

---

### GAP 2 — B71 (security-tcred.test.ts)

**Problem:** Heuristic "string > 20 chars" test was fragile and always passed vacuously when auth.json absent.

**Fix approach:** Static contract on `packages/pi-coding-agent/src/core/auth-storage.ts` — the actual class that writes auth.json. Verified file contains `chmodSync` at 3 call sites with `0o600`.

**Test type:** Static contract (Tier 3, permitted by RESEARCH.md)

**Verification:** `chmodSync` and `0o600` confirmed present at lines 66, 81, 119. Test passes.

---

### GAP 3 — B62 (security-tcred.test.ts)

**Problem:** No test existed for `changeProvider()` invoking `delete_credential` on logout.

**Fix approach:** Static contract test on `src/auth/auth-api.ts`. Confirmed:
- `KEYCHAIN_CREDENTIAL_KEYS` is defined (const array of 5 keys)
- `invoke("delete_credential"` appears in `changeProvider`
- `Promise.allSettled` is used (failures don't block logout)
- `keys.map(key =>` pattern confirmed
- `export async function changeProvider` confirmed

**Rationale for Tier 3:** `@tauri-apps/api/core` cannot be imported in Bun subprocess tests (no Tauri webview context). The source inspection directly verifies the exact call site.

**Test type:** Static contract (Tier 3)

---

### GAP 4 — B72 (security-tcred.test.ts)

**Problem:** Prior test only matched the function signature regex; a function could have the `window:` parameter but never call `require_main_window`.

**Fix approach:** After locating each function's start offset in the source, slices up to the next `pub async fn` boundary and asserts `require_main_window` appears in that body text. Applied to all 4 sensitive commands: `set_credential`, `delete_credential`, `get_credential`, `restart_bun`.

**Verification:** All 4 functions confirmed to call `require_main_window(&window)` in their bodies. Test passes.

---

### GAP 5 — B45/B46/B47 (security-tnet.test.ts)

**Problem:** `it.todo()` entries never executed — counted as neither pass nor fail, leaving coverage gap.

**Fix approach:**
1. Converted `it.todo()` to `it.skip()` with inline comment referencing the Rust unit test name (`test_poisoned_mutex_does_not_panic`) and the `cargo test -p mission-control-lib` command.
2. Added a live static contract test that reads `bun_manager.rs` and counts `.lock().unwrap_or_else` occurrences — must be >= 3.

**Verification:** `bun_manager.rs` has exactly 3 `unwrap_or_else` calls at lock sites (lines 122, 150, 182). Static test passes. 3 `it.skip` entries appear in the test output as "3 skip".

---

### GAP 6 — B38 (security-tnet.test.ts)

**Problem:** `if (regRes.status !== 200 || !regBody.wsPort) { return; }` caused silent vacuous pass without testing the Origin rejection.

**Fix approach:**
- Added `connectionWasRejected = false` flag, set to `true` in both `onerror` and `onclose` handlers.
- After the Promise resolves, asserts `expect(connectionWasRejected).toBe(true, ...)`.
- Added a fallback static contract branch: if registration is unavailable, reads `ws-server.ts` and asserts `origin|Origin` pattern is present — preventing silent skips.

---

### GAP 7 — B70 (security-txss.test.ts)

**Problem:** Two nested `try { readFileSync(...) } catch { /* skip */ }` blocks allowed the test to pass even if both candidate files were absent.

**Fix approach:**
- Added `existsSync` import.
- Pre-check both candidate paths with `existsSync`.
- Assert `libExists || rootExists` with a meaningful failure message pointing to the correct path to add.
- Only call `readFileSync` when existence is confirmed (no swallowed errors).
