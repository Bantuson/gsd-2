Modify `packages/mission-control/src/server/ws-server.ts` to scope the planning-state topic per windowId:

1. Change the constant `TOPIC` to a prefix: `const TOPIC_PREFIX = "planning-state:";`

2. In the `fetch()` handler (the HTTP upgrade path), extract the windowId from the query string:
   ```typescript
   const windowId = url.searchParams.get("windowId") || "default";
   ```
   Pass the windowId to the websocket `open` handler via the `data` field on upgrade. Bun's `server.upgrade(req, { data: { windowId } })` sets `ws.data` on the resulting ServerWebSocket.

3. In `websocket.open(ws)`:
   - Read `windowId` from `(ws as any).data?.windowId || "default"`
   - Subscribe to the scoped topic: `ws.subscribe(TOPIC_PREFIX + windowId)` instead of `ws.subscribe(TOPIC)`
   - Still subscribe to `CHAT_TOPIC` (chat is shared, not per-window)

4. In `websocket.close(ws)`:
   - Read windowId same way: `(ws as any).data?.windowId || "default"`
   - Unsubscribe from `TOPIC_PREFIX + windowId` instead of `TOPIC`

5. Change the `broadcast(diff)` method to accept an optional windowId parameter. The signature becomes:
   ```typescript
   broadcast(diff: StateDiff, windowId?: string): void
   ```
   - If windowId is provided: `server.publish(TOPIC_PREFIX + windowId, JSON.stringify(diff))`
   - If no windowId (backward compat): publish to `TOPIC_PREFIX + "default"`

6. Update the `WsServer` interface to match: `broadcast(diff: StateDiff, windowId?: string): void;`

7. Keep backward compatibility: if no `windowId` query param is provided, clients get the "default" topic (same as current behavior for single-window usage).

Important: Do NOT change the CHAT_TOPIC behavior — chat is broadcast to all clients. Only planning-state needs per-window isolation.
