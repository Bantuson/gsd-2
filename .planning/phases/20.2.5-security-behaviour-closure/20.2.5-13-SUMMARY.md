# Phase 20.2.5 Plan 13: WS Session Isolation (B52) Summary

**Per-window planning-state topic scoping via TOPIC_PREFIX + windowId; B52 isolation test passes GREEN with zero cross-session message leakage**

## Performance

- **Duration:** ~5 min
- **Started:** 2026-03-24T16:18:18Z
- **Completed:** 2026-03-24T16:23:02Z
- **Tasks:** 2
- **Files modified:** 2

## Accomplishments

- Replaced single shared `TOPIC = "planning-state"` constant with `TOPIC_PREFIX = "planning-state:"` prefix
- Clients now subscribe to `planning-state:<windowId>` — two windows cannot receive each other's state diffs
- `broadcast(diff, windowId?)` accepts optional windowId for targeted delivery; defaults to "default" for backward compatibility
- `server.upgrade(req, { data: { windowId } })` passes window identity into WS open/close handlers via `ws.data`
- B52 `it.todo()` replaced with a real test that connects two WS clients and asserts zero cross-window message leakage

## Task Commits

1. **Task 1: Add per-window topic scoping to ws-server.ts** - `5cfe0e45` (feat)
2. **Task 2: Implement B52 session isolation test** - `ae5c4d1e` (test)

## Files Created/Modified

- `packages/mission-control/src/server/ws-server.ts` — Changed TOPIC to TOPIC_PREFIX, extract windowId from upgrade query, subscribe/unsubscribe per-window, broadcast accepts windowId param
- `packages/mission-control/tests/security-tauth.test.ts` — Replaced B52 it.todo() with actual isolation test using two WS clients with different windowIds

## Decisions Made

- Used `url.searchParams.get("windowId") || "default"` for backward compat — single-window installs not breaking
- Used `(ws as unknown as { data?: { windowId?: string } }).data?.windowId` to avoid Bun's ServerWebSocket generic type limitation
- B52 test creates its own WS server on random port 14300-14399 (independent of startTestServer) to avoid per-launch token coupling

## Deviations from Plan

None — plan executed exactly as written. The `const url = new URL(req.url)` extraction was refactored to be shared between the token check and windowId extraction (minor DRY improvement, no behavior change).
