**Step 2 — Create a shared sanitization helper:**
Create `packages/mission-control/src/lib/sanitize-html.ts`:
```typescript
import DOMPurify from "dompurify";

/**
 * Sanitize HTML output from markdown rendering before DOM insertion.
 * Removes <script> tags, javascript: URLs, event handler attributes,
 * and all other XSS vectors identified in T-EXEC-02.
 *
 * SECURITY: This is the DOMPurify sanitization layer required by B25, B65.
 * Do NOT bypass or disable this function.
 */
export function sanitizeHtml(rawHtml: string): string {
  return DOMPurify.sanitize(rawHtml, {
    // Explicitly allow only safe HTML elements
    ALLOWED_TAGS: [
      "p", "br", "strong", "em", "b", "i", "u", "s", "code", "pre",
      "ul", "ol", "li", "blockquote", "h1", "h2", "h3", "h4", "h5", "h6",
      "a", "img", "table", "thead", "tbody", "tr", "th", "td",
      "div", "span", "hr",
    ],
    // Block all event handlers and javascript: URLs
    ALLOWED_ATTR: ["href", "src", "alt", "title", "class", "id", "target", "rel"],
    // Force all links to be safe
    FORCE_BODY: true,
    // Forbid data: URIs in href/src (potential XSS vector)
    ALLOW_DATA_ATTR: false,
    // Custom hook: reject javascript: hrefs
    RETURN_DOM: false,
  });
}
```

**Step 1 — Update tauri.conf.json CSP (B28, B29, B67):**
Read the current CSP string in `app.security.csp`:
```
"default-src 'self' http://127.0.0.1:4200; connect-src http://127.0.0.1:4200 ws://127.0.0.1:* ws://localhost:* 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:"
```

Replace with a hardened CSP:
```json
"csp": "default-src 'self' http://127.0.0.1:4200; connect-src http://127.0.0.1:4200 http://127.0.0.1:4001 http://127.0.0.1:4002 http://127.0.0.1:4003 http://127.0.0.1:4004 http://127.0.0.1:4005 http://127.0.0.1:4006 http://127.0.0.1:4007 http://127.0.0.1:4008 http://127.0.0.1:4009 http://127.0.0.1:4010 ws://127.0.0.1:4001 ws://127.0.0.1:4002 ws://127.0.0.1:4003 ws://127.0.0.1:4004 ws://127.0.0.1:4005 ws://127.0.0.1:4006 ws://127.0.0.1:4007 ws://127.0.0.1:4008 ws://127.0.0.1:4009 ws://127.0.0.1:4010 https://api.anthropic.com; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:"
```

Key changes:
- `script-src 'self'` — removes `'unsafe-inline'` (fixes B28)
- No nonce in static CSP — Tauri 2.x injects nonces at runtime per window. The `'self'` directive
  is the Tauri 2.x recommended approach. Document this: `// B29: Tauri 2.x uses 'self' for bundled scripts; runtime nonces injected by WebView`
- `connect-src` lists specific WS ports 4001-4010 instead of wildcard (fixes B67)
- Adds `https://api.anthropic.com` explicitly for AI provider

IMPORTANT: The style-src keeps `'unsafe-inline'` — Tailwind CSS requires this. This is
an accepted trade-off for a desktop-only app. Add a comment explaining this.

Also update `assetScope` in `plugins.protocol` (B76):
```json
"assetScope": {
  "allow": ["$RESOURCE/**", "$APP/public/**", "$APP/dist/**"],
  "deny": []
}
```
This narrows from `$APP/**` to specific UI asset subdirectories.

**Step 2 — Create secondary-window capability file (B30, B31, B72):**
Create `packages/mission-control/src-tauri/capabilities/secondary-window.json`:
```json
{
  "$schema": "https://schema.tauri.app/config/2/capability",
  "identifier": "secondary-window",
  "description": "Capabilities for secondary windows (preview, code viewer). Excludes all credential and process management commands per B30/B31.",
  "windows": ["window-*", "preview-*", "viewer-*"],
  "permissions": [
    "core:default",
    "dialog:default"
  ]
}
```

The `permissions` list deliberately EXCLUDES:
- `keychain:*` / `set_credential` / `delete_credential` / `get_credential`
- `bun-manager:restart_bun`

Secondary windows only get `core:default` (basic IPC) and `dialog:default` (file picker).

**Step 3 — Add sandbox to preview iframes (B32):**
Read DeviceFrame.tsx and PreviewPanel.tsx. Find every `<iframe` element.

Add the sandbox attribute:
```tsx
// BEFORE:
<iframe src={previewUrl} className="..." />

// AFTER (B32: sandbox required on all preview iframes):
<iframe
  src={previewUrl}
  className="..."
  sandbox="allow-scripts allow-same-origin allow-forms"
  // B32: sandbox prevents iframe from accessing parent frame APIs
  // allow-same-origin is needed for preview to load assets; allow-scripts for JS preview
/>
```

IMPORTANT: Do NOT use `sandbox="allow-scripts allow-same-origin"` without documentation.
The THREAT-MODEL says this combination is dangerous unless strictly required. In this case,
preview iframes need it to render React apps. Add comment explaining necessity and risk acceptance.

If any iframe ONLY shows static content (no JS needed), use `sandbox="allow-same-origin"` only.
