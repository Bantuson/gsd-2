# Phase 20.2.1 Plan 02: Async Sleep Fix + Production Start Script Summary

Replace Tokio executor-blocking `std::thread::sleep` calls in `bun_manager.rs` with `tokio::time::sleep` and add a production `start` script to `package.json` for Tauri builds.

## What Was Built

**B5 — Async sleep fix:** Both `std::thread::sleep` calls in `bun_manager.rs` replaced with `tokio::time::sleep(...).await`. The `watch_bun_process` loop now yields to the Tokio executor every 2 seconds instead of blocking its thread; `restart_bun` delays 500ms non-blocking before respawning Bun. The `tokio` dependency in `Cargo.toml` was extended from `["rt"]` to `["rt", "time"]` to enable the time module.

**S2 — Production start script:** A `"start"` script (`bun run src/server.ts`) added to `package.json` alongside the existing `"dev"` script (which uses `--hot`). The `spawn_bun_server` function in `bun_manager.rs` now uses `.arg("start")` instead of `.arg("dev")`, ensuring Tauri production builds run the server without HMR.

**Tests:** 7 source-text tests in `production-start.test.ts` assert the above invariants — no `std::thread::sleep` in source, correct tokio sleep forms, Cargo.toml feature list, package.json start script shape, and bun_manager spawn command.
