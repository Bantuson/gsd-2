<decisions>
## Implementation Decisions

### B1 — Tauri Updater Pubkey (BLOCKER)
- File: `packages/mission-control/src-tauri/tauri.conf.json`
- Problem: `"pubkey": ""` — updater will accept any payload (MITM risk)
- Fix: Generate key pair with `cargo tauri signer generate`, embed the public key in `tauri.conf.json`
- The private key goes into GitHub Actions secret `TAURI_SIGNING_PRIVATE_KEY` (already wired in release.yml)
- The public key is NOT secret — it is safe to commit to the repo

### B2 — URL Scheme Allowlist in open_external / reveal_path (BLOCKER)
- File: `packages/mission-control/src-tauri/src/commands.rs`
- Problem: `open_external` opens any URL the WebView sends — no scheme validation
- Fix for `open_external`: validate `url.starts_with("https://") || url.starts_with("http://")` before calling `open_url`; return `false` if invalid
- Problem: `reveal_path` passes untrusted path directly to `opener().reveal_item_in_dir`
- Fix for `reveal_path`: validate path is absolute and does not escape expected directories (at minimum validate it's not a relative path injection)

### B3 — Credential Key Allowlist (BLOCKER)
- File: `packages/mission-control/src-tauri/src/commands.rs`
- Problem: `get_credential(key)` and `set_credential(key, value)` accept any key string from the WebView
- Fix: Add `const ALLOWED_CREDENTIAL_KEYS: &[&str] = &["anthropic_api_key", "github_token", ...];` (enumerate all valid keys)
- Validate `key` against the allowlist before calling `keyring::Entry::new`; return `None` / error if not allowed

### B4 — server.ts: no_project_loaded gate (BLOCKER)
- File: `packages/mission-control/src/server.ts`
- Problem: `registerWindow` always creates a pipeline pointing at `resolve(repoRoot, ".gsd")` — the monorepo's own planning dir
- Fix: Emit a `no_project_loaded` state event to the WebSocket before any project is opened
- Gate: Chat sends (agent invocations) must be rejected with a clear error if no project has been explicitly selected via `/api/project/switch`
- Ideal: `planningDir` starts as `null`; pipeline refuses to spawn `gsd` until set
- Acceptable minimum: Pipeline is created with monorepo path BUT state emits `{ type: "no_project_loaded" }` and the server rejects `/api/pipeline/*` chat messages until `switchProject` has been called at least once per window

### B5 — tokio::time::sleep in watch_bun_process (BLOCKER)
- File: `packages/mission-control/src-tauri/src/bun_manager.rs`
- Problem: `std::thread::sleep(Duration::from_secs(2))` inside an `async fn` starves the Tokio executor
- Fix: Replace with `tokio::time::sleep(std::time::Duration::from_secs(2)).await`
- Add `tokio` dependency if not already in `Cargo.toml` with `features = ["time"]`

### B6 — CORS headers on frozen Bun Response (BLOCKER)
- File: `packages/mission-control/src/server.ts`
- Problem: `addCorsHeaders(response)` calls `response.headers.set(...)` on a Response returned by `Response.json()` which may be frozen in Bun
- Fix: Verify behavior; if frozen, reconstruct response:
  ```ts
  function addCorsHeaders(response: Response): Response {
    const headers = new Headers(response.headers);
    headers.set("Access-Control-Allow-Origin", `http://127.0.0.1:${HTTP_PORT}`);
    headers.set("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS");
    headers.set("Access-Control-Allow-Headers", "Content-Type, X-Window-Id");
    return new Response(response.body, { status: response.status, headers });
  }
  ```

### S1 — Remove continue-on-error from pr-check.yml (HIGH PRIORITY)
- File: `.github/workflows/pr-check.yml`
- Fix: Remove `continue-on-error: true` from the unit tests step
- All 235 tests must pass before merge — they are now fixed (0 failures locally)

### S2 — Production start script vs dev (HIGH PRIORITY)
- File: `packages/mission-control/package.json` + `src-tauri/src/bun_manager.rs`
- Problem: `bun_manager.rs` spawns `bun run dev` in the bundled app — this uses HMR/TypeScript source, not compiled output
- Fix: Add `"start": "bun run src/server.ts"` or `"start": "node dist/server.js"` script to `package.json`
- Update `bun_manager.rs` to use `"start"` instead of `"dev"` when launching the server in production
- Note: compiled server entry point should be determined by what `beforeBuildCommand` produces

- Exact `start` script command — depends on what the build step produces
- Whether `no_project_loaded` gate is implemented at server level (reject HTTP) or at WS level (emit state)
