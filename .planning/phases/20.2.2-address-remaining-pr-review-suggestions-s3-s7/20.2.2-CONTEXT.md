<decisions>
## Implementation Decisions

### S3 — %2E%2E path traversal test (fs-api.ts)
- File: `packages/mission-control/tests/` (new test file or add to existing fs-api tests)
- Reviewer concern: `url.searchParams.get("path")` returns the decoded string from Bun, so `%2E%2E` decodes to `..` before reaching the handler — the check should catch it. But there is no test documenting this assumption.
- Fix: Add a test case that sends a request with `path=%2E%2E%2F..%2Fetc%2Fpasswd` and asserts it is rejected with the path traversal error
- This is a documentation-as-test fix, not a code change in the handler

### S4 — Merge action silent delete in session-manager.ts
- File: `packages/mission-control/src/server/session-manager.ts`
- Reviewer concern: The `merge` case in `closeSessionWithWorktree` silently falls through to delete behavior. The UI exposes merge as a first-class option.
- Fix: Remove the merge option from the UI (simpler, avoids shipping a broken feature) OR return a clear error from the merge case so the client can show a message
- Decision: Return an error response from the merge case with message "Merge not yet implemented — use discard or keep" so the user gets feedback instead of silent delete. This is safer than removing from UI without knowing the full UI component tree.

### S5 — WS auth comment (ws-server.ts)
- File: `packages/mission-control/src/server/ws-server.ts` (or wherever the WS upgrade handler lives)
- Reviewer concern: No authentication on WS connections. Any local process can subscribe to chat output or inject messages.
- Fix: Add a code comment above the upgrade handler explicitly noting: (1) server binds to 127.0.0.1 only, (2) the local-process threat is an accepted risk for a desktop app, (3) the X-Window-Id header is used for routing but not security validation
- No code change required, comment only

### S6 — releaseDraft: true breaks OTA (release.yml)
- File: `.github/workflows/release.yml`
- Reviewer concern: `tauri-plugin-updater` endpoints point to `releases/latest/download/latest.json`. GitHub "latest" excludes draft releases. So every automated build produces a draft that silently fails OTA until manually published.
- Fix: Set `releaseDraft: false` so releases are published immediately and OTA works automatically
- If there is a reason drafts are preferred (manual QA gate), add a comment explaining the manual publish step is required for OTA

### S7 — Window label race condition (commands.rs)
- File: `packages/mission-control/src-tauri/src/commands.rs`
- Reviewer concern: `open_new_window` uses `SystemTime::now().as_millis()` as the window label. Two rapid clicks within the same millisecond produce duplicate labels, which Tauri rejects with a user-visible error.
- Fix: Use an atomic counter in `AppState` (already exists in the codebase) to generate unique window labels: `window-1`, `window-2`, etc.
- The counter should be a `std::sync::atomic::AtomicU64` incremented with `fetch_add(1, Ordering::SeqCst)`

</decisions>
